# テキスト読み上げ API サーバー 要件定義書

## 1. プロジェクト概要

このプロジェクトは、Cartesia API を利用したテキスト読み上げ（TTS: Text-to-Speech）サービスを FastAPI で実装した API サーバーです。テキスト入力を受け取り、音声合成を行い、PCM 形式でストリーミング配信する機能を提供します。文単位での高品質な音声合成とリアルタイムストリーミングを実現し、モジュール化された設計により拡張性と保守性を重視しています。また、ウェブインターフェース（Next.js）による利用も想定された構成になっています。

## 2. 目的

テキストを高品質な音声に変換し、様々なアプリケーションやサービスで利用可能な形で提供することを目的としています。PCMストリーミング配信により即座の音声再生を実現します。

## 3. 機能要件

### 3.1 コア機能

- **テキスト音声変換 (TTS)**
  - テキスト入力を受け取り、自然な音声に変換
  - 言語サポート: 日本語（デフォルト）
  - 複数の音声パラメータ（速度、サンプルレート、ピッチなど）のカスタマイズ
  - 声の選択（voice_id 指定による）

### 3.2 API 機能

- **PCMストリーミング配信 (`POST /tts/stream`)**

  - リアルタイム PCM s16le ストリーミング配信による即座の音声再生
  - 文単位での処理により高品質な音声を実現
  - デバッグ用PCMファイル保存機能付き

- **PCMバイナリデータ取得 (`POST /tts/bytes`)**

  - テキストから音声に変換したPCM s16le形式のバイナリデータを直接返す
  - ストリーミングではなく完全なデータを一度に取得

### 3.3 追加機能

- **文単位処理とNLP統合**

  - GINZA（日本語NLP）による高精度な文分割
  - 各文ごとの独立した音声合成処理
  - 文間の自動ポーズ挿入（0.2秒のサイレンス）

- **音声形式**

  - PCM s16le形式でのリアルタイムストリーミング（48kHz, 16bit, モノラル）

- **認証システム**

  - APIキー認証による基本的なアクセス制御
  - 開発環境での認証スキップ機能

- **ファイル管理**
  - 一時ファイル自動クリーンアップ（24 時間経過分）
  - デバッグ用PCMファイル自動保存
  - ストリーミング終了後のリソース自動解放

## 4. 非機能要件

### 4.1 性能要件

- **レスポンス速度**

  - リアルタイム処理：標準的なテキスト（100 文字程度）で 3 秒以内のレスポンス
  - 非同期処理：バックグラウンド処理による負荷分散

- **同時処理能力**

  - 複数リクエストの同時処理

- **データ形式**
  - 音声出力：PCM s16le形式
  - サンプルレート：44100Hz
  - チャンネル：モノラル（1チャンネル）
  - ビット深度：16bit

### 4.2 信頼性要件

- **エラーハンドリング**

  - API 通信エラー時の適切な例外処理
  - 音声データ処理失敗時のフォールバック処理

- **データ保持**
  - 生成ファイルの一時保存（24 時間）

### 4.3 セキュリティ要件

- **認証**
  - API キーによるアクセス制限（X-API-Keyヘッダー）
  - 開発環境での認証スキップ機能
  - 設定ファイル（.env）を通じた API 認証情報の管理

### 4.4 運用要件

- **コンテナ化**

  - Docker を使用した環境構築サポート
  - docker-compose による関連サービス（PostgreSQL など）との連携

- **監視・ログ**
  - 適切なログ出力
  - 処理エラーの記録

## 5. インターフェース要件

### 5.1 API 仕様

#### PCMストリーミング配信

```
POST /tts/stream
```

**リクエスト本文:**

```json
{
  "text": "変換するテキスト",
  "voice_id": "2334b692-d045-48b5-ac45-d7bf5785026f",
  "language": "ja",
  "speed": "normal"
}
```

**レスポンス:**

- Content-Type: audio/pcm
- PCM s16le形式の音声データをストリーミング配信
- ヘッダー情報: サンプルレート44100Hz、1チャンネル、16bit深度

#### PCMバイナリデータ取得

```
POST /tts/bytes
```

**リクエスト本文:**

```json
{
  "text": "変換するテキスト",
  "voice_id": "2334b692-d045-48b5-ac45-d7bf5785026f",
  "language": "ja",
  "speed": "normal"
}
```

**レスポンス:**

- Content-Type: audio/pcm
- PCM s16le形式の音声バイナリデータ（48kHz, 16bit, モノラル）

### 5.2 ウェブインターフェース

- Next.js + Material UI を使用したフロントエンドの実装
- **テスト用の位置付け**：フロントエンドは API のテストと機能検証を主目的としたもの
- **UI テーマ**：GitHub UI を参考にしたデザインを採用
- PCM音声の再生機能を提供
- リアルタイム音声ストリーミング対応

## 6. 技術要件

### 6.1 サーバーサイド

- **言語**

  - Python 3.12

- **フレームワーク**

  - FastAPI

- **主要ライブラリ**

  - cartesia: 音声合成 API 連携
  - numpy: 配列操作と数値計算
  - scipy: 音声データリサンプリング（オプション）
  - ja-ginza, ja-ginza-electra: 日本語自然言語処理（文分割）
  - fugashi, ipadic: 日本語形態素解析
  - uvicorn: ASGI サーバー
  - python-dotenv: 環境変数管理
  - ffmpeg-python: 音声処理補助（オプション）

- **アーキテクチャ**
  - モジュール分割: APIルーター、サービス層、ユーティリティの分離
  - 共通ライブラリ: 機能の重複を避け、再利用性を高めたモジュール設計
  - クリーンアーキテクチャ: UI層・アプリケーション層・ドメイン層の分離を意識した設計
  - PCM専用最適化: 音声フォーマットをPCMに特化した軽量なAPI設計（2つのエンドポイント）

### 6.2 データベース

- **PostgreSQL**
  - Docker イメージを使用（postgres:16.3-alpine）
  - 現状はジョブ管理はメモリ内で行っているが、将来的には DB に移行予定

### 6.3 フロントエンド

- **フレームワーク**

  - Next.js 15.3.3
  - React 19.0.0

- **UI ライブラリ**
  - Material UI 7.1.0

### 6.4 デプロイメント

- **コンテナ化**
  - Docker
  - docker-compose

## 7. 制約条件

- **外部依存性**

  - Cartesia API キーが必要
  - インターネット接続が必要（Cartesia API 通信用）

- **環境要件**
  - PyAudio 関連の依存ライブラリ（libasound-dev, portaudio19-dev など）
  - Python 3.10 以上

## 8. リスク

- **API 依存性**

  - Cartesia API の仕様変更や障害に影響を受ける可能性

- **システムリソース**

  - 大量リクエスト時のメモリ使用量や処理遅延
  - 保存ファイルの容量増大（自動クリーンアップで対応）

- **互換性**
  - 音声フォーマットの互換性（PCM 形式の標準化）

## 8.1 コード構成とモジュール分割

- **モジュール設計**
  - PCM専用に最適化されたシンプルな構成
  - サーバー (`api.py`) とコマンドライン (`main.py`) の両方から共通機能を利用可能
  - 重複機能を排除した簡潔なAPI設計（2つのエンドポイント）
